VisionScript: Multimodal Image Captioning

Exploring how visual representations can be connected to language generation, from a BLIP captioning baseline to CLIP-conditioned GPT-2 experiments and interactive visual question answering.

THE PROBLEM

How do you get a model to describe what is actually in an image?

VisionScript explored the connection between images and natural language. The goal was to build a system that could take visual information and turn it into useful language, while also exploring how different vision-language architectures behave.

Rather than jumping directly to one final model, the project developed progressively across four milestones, starting with a pretrained captioning baseline and moving toward a more interactive multimodal system.

THE BASELINE

Starting with a model that already knows how to caption images.

The first milestone established a baseline using BLIP's pretrained image-captioning capabilities. We worked with the Flickr30k dataset, including preprocessing and creating a subset of roughly 1,000 image-caption pairs for experimentation.

CLIP embeddings were also extracted and cached, while the GPT-2 tokenizer was used to examine caption characteristics such as length.

The baseline successfully generated fluent, generally image-grounded captions, but the results were not perfect. That made the baseline useful as a reference point for the experiments that followed.

CLIP + GPT-2

What happens when visual information is explicitly injected into a language model?

The next milestone explored a different approach to multimodal generation. Instead of relying on an already integrated captioning model, the system used CLIP to encode the image and GPT-2 to generate the language.

The visual representation was projected into a form that could be passed into GPT-2 as part of the generation process. This created a direct connection between the visual input and the language-generation stage.

Different decoding strategies were also explored, including greedy decoding, beam search, and nucleus sampling. The experiments showed that decoding strategy can affect how natural, structured, or repetitive the resulting captions become.

FINE-TUNING EXPERIMENTS

Different ways of adapting the language model produced different behavior.

The third milestone compared several approaches for adapting the CLIP-GPT-2 system: Prefix Tuning, LoRA, and full fine-tuning. The pretrained BLIP model was also retained as a baseline for comparison.

The experiments highlighted an important trade-off. Parameter- efficient approaches such as Prefix Tuning and LoRA reduce the amount of the model that needs to be trained, but the resulting caption quality can vary depending on the image.

In the documented test examples, BLIP produced the most consistently accurate descriptions. LoRA generally produced more relevant descriptions than Prefix Tuning, while full fine-tuning could produce more descriptive outputs but also showed cases of overfitting or incorrect descriptions.

I was not the primary contributor to these fine-tuning implementations, so I treat this milestone mainly as an important part of the project's comparative experimentation.

FINAL SYSTEM

From generating one caption to supporting different ways of understanding an image.

The final VisionScript system used BLIP and expanded the interaction beyond a single generated sentence. Users could choose between a short caption, a more detailed paragraph, or a question-answering mode.

The paragraph mode was designed to provide richer descriptions involving context and relationships, while VQA allowed the user to ask questions about the contents of an image.

The interface was developed as a team effort, including work with another teammate.

RESULTS

The final system supported three different forms of visual understanding.

SINGLE

Short, concise image descriptions that provide a quick summary of the visual input.

PARAGRAPH

More detailed descriptions with additional context and relationships between elements in the image.

VQA

Question answering over the image, allowing users to interact with visual information through natural language.

The final system worked particularly well with clear subjects and outdoor scenes. Paragraph generation could sometimes become slightly verbose or repetitive, showing that richer output is not automatically better output.

WHAT I LEARNED

The interesting part isn't just getting an image and a sentence. It's the connection between them.

The biggest thing I took away from this project was understanding how image and text pairs are used to train and evaluate multimodal systems.

Before working on VisionScript, I understood image models and language models more independently. This project helped me see how a visual representation can be connected to language generation and how the quality of the generated language has to be considered alongside whether it is actually grounded in the image.

It also showed me that fluent language alone is not enough. A caption can sound completely reasonable while still describing the image incorrectly.

MY ROLE

Contributing across the project, with the baseline as my clearest area of hands-on work.

I contributed across different parts of the project as part of the four-person team. My clearest area of hands-on involvement was the initial BLIP captioning work, including working with the image-caption data, preprocessing, running the baseline, and looking at the generated captions.

I also participated in the broader development and experimentation that moved the project from a basic captioning baseline toward a multimodal interface with multiple interaction modes.

I would not describe the individual fine-tuning implementations or the complete VQA system as solely my work. Those parts were developed as team efforts.

TAKEAWAYS

Multimodal systems are about connecting the pieces, not just choosing a model.

VisionScript gave me a practical introduction to how vision and language models can work together. The project moved from a pretrained baseline through several modeling experiments and eventually into an interactive system.

More importantly, it helped me understand what sits between an image and a generated answer: visual representations, language modeling, conditioning, decoding, evaluation, and the problem of keeping generated language grounded in the input.

REFLECTION

If I rebuilt it, I would make the architecture easier to compare and extend.

I would make the different modeling approaches more modular so that the vision encoder, representation layer, language model, and evaluation pipeline could be changed and compared more easily.

That would make it easier to experiment with different multimodal architectures while keeping the evaluation process consistent.
